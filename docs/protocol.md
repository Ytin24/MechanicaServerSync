# Протокол Mechanica Server Sync 1.0

Общий протокол для вариантов мода под разные Minecraft и загрузчики. Сервер объявляет адрес описания в Minecraft status, публикует список по HTTP/HTTPS; клиентский мод связывается с лаунчером через локальный IPC.

Настройка сервера и сборка JAR: [README](../README.md). Документ адаптирован из [описания в Mechanica Launcher](https://github.com/Ytin24/MechanicaLauncher/blob/master/docs/server-mod-sync.md).

## Участники и порядок работы

- Серверный мод публикует JAR, явно перечисленные в `config/mechanica-sync.json` и находящиеся в `client-pack`.
- Клиентский мод перехватывает попытку подключения и передаёт адрес лаунчеру. Сам он не скачивает моды и не изменяет `mods`.
- Лаунчер получает URL описания из status сервера либо явно сохранённой настройки. Он получает список, запрашивает согласие, проверяет файлы, применяет изменения и управляет повторным запуском.

Синхронизация включается для конкретной сборки через **Mechanica Server Sync**. Отдельное разрешение «Автодокачка модов» относится к сохранённому серверу. Без разрешения на автоматическую установку лаунчер показывает план изменений. Изменение адреса, URL списка или сборки снимает прежнее разрешение.

Проверка выполняется до соединения с игровым сервером. Из экрана серверов лаунчер может выполнить её до запуска Minecraft. При подключении из игры мост ждёт ответа лаунчера. Если изменений нет, подключение продолжается сразу. Если нужны моды, лаунчер скачивает их во временный каталог; мост штатно завершает игру, и изменения применяются после выхода соответствующей JVM. Затем лаунчер запускает ту же сборку с исходным адресом. Допускается один автоматический повторный запуск; изменившийся после него список останавливает цикл.

## Обнаружение до входа

Если для host/port и выбранной сборки нет сохранённого URL, лаунчер выполняет обычный Minecraft status ping. В корне JSON-ответа сервер публикует необязательное поле:

```json
"mechanica": {"protocol": 1, "descriptorUrl": "https://mods.example.org/mechanica/descriptor.json"}
```

`protocol` — целое `1`; `descriptorUrl` — абсолютный HTTPS URL длиной до 2048 символов, без данных входа и fragment. HTTP разрешён для теста, только когда игровой host и URL host — буквальные loopback IP. Все обычные поля status, включая MOTD, игроков и favicon, сохраняются. Объявление добавляется только после успешного запуска HTTP-компонента и исчезает при его остановке. URL формируется из настроенного `baseUrl`, порт и путь не угадываются.

Явно сохранённый URL имеет приоритет. Без объявления или при недоступном status продолжается обычное подключение; некорректное объявление возвращает ошибку. Обнаружение не создаёт запись в избранном и не разрешает автоматическую установку: при изменениях требуется подтверждение с источником загрузки. Проверка происходит до входа и до отказа загрузчика из-за отсутствующих модов.

Автообнаружение требует обновления серверного JAR и лаунчера. Старые серверные JAR работают с явно сохранённым URL.

## HTTP: описание и манифест

JSON передаётся в UTF-8. URL описания берётся из объявления либо явно сохранённой настройки. Текущий серверный мод публикует три вида GET-ресурсов:

| Путь | Содержимое |
| --- | --- |
| `/mechanica/descriptor.json` | Версии протокола и точная целевая сборка |
| `/mechanica/manifests/<revision>.json` | Утверждённый список клиентских модов |
| `/mechanica/files/<sha512>/<filename>` | Явно опубликованный JAR |

Публикация создаётся при запуске сервера. Размеры и хеши вычисляются по байтам файлов. Если `revision` не задана в конфиге, серверный мод хранит её в `config/mechanica-sync.state.json` и увеличивает сам, когда меняется опубликованный набор; иначе после изменения конфигурации или JAR администратор увеличивает `revision` и перезапускает сервер. Протокол и формат ответов от этого не меняются. Файл, изменённый после публикации, не отдаётся по старому адресу.

Лаунчер выполняет следующие шаги:

1. Получает сохранённый или объявленный descriptor URL без добавления своего пути или query.
2. Проверяет `descriptorVersion`, выбирает общую версию протокола и проверяет обязательные возможности.
3. Находит target по точным `minecraft`, `loader`, `loaderVersion` и получает его `manifestUrl`.
4. Проверяет SHA-512 исходных байтов манифеста, затем протокол, сервер, target, ревизию и срок действия.

Текущая версия — `descriptorVersion: 1`, протокол `1.0`, обязательная возможность `mods-v1`. Неизвестная обязательная возможность или отсутствие общей версии дают ошибку; неудачная проверка не разрешает переход на менее строгий формат.

Примеры ниже показывают форму ответа. Хеши и имена файлов необходимо заменить реальными; серверный мод делает это автоматически.

```json
{
  "descriptorVersion": 1,
  "serverId": "b3a38c5e-593c-4bdd-9046-e019b3453eb0",
  "protocols": [{
    "major": 1,
    "minor": 0,
    "requiredCapabilities": ["mods-v1"],
    "targets": [{
      "targetId": "fabric-1.20.1",
      "minecraft": "1.20.1",
      "loader": "fabric",
      "loaderVersion": "0.19.5",
      "manifestUrl": "https://mods.example.org/mechanica/manifests/7.json",
      "sha512": "<sha512 исходных байтов манифеста>"
    }]
  }]
}
```

```json
{
  "type": "Manifest",
  "protocolMajor": 1,
  "protocolMinor": 0,
  "serverId": "b3a38c5e-593c-4bdd-9046-e019b3453eb0",
  "targetId": "fabric-1.20.1",
  "revision": 7,
  "expiresUtc": "2027-01-01T00:00:00Z",
  "minecraft": "1.20.1",
  "loader": "fabric",
  "loaderVersion": "0.19.5",
  "files": [{
    "artifactId": "example-client-mod",
    "modIds": ["example_client_mod"],
    "client": "required",
    "filename": "example-client-mod.jar",
    "size": 123456,
    "sha512": "<sha512 файла>",
    "dependencies": [],
    "source": {
      "type": "external",
      "url": "https://mods.example.org/mechanica/files/<sha512>/example-client-mod.jar"
    }
  }]
}
```

### Поля и ограничения

`serverId` — UUID, идентификатор сервера, а не подтверждение доверия. `targetId` и `artifactId` — регистрозависимые строки `[a-z0-9][a-z0-9._-]{0,63}`. Версия Minecraft сравнивается как точный ID. Серверный компонент поддерживает названия загрузчиков `fabric`, `quilt`, `forge`, `neoforge`; это не означает совместимость каждого JAR с каждым загрузчиком.

`revision` растёт для пары serverId/targetId и находится в диапазоне `1..9007199254740991`. Изменение состава или срока действия требует новой ревизии. `expiresUtc` — будущий момент UTC с окончанием `Z`. Хеши — SHA-512 в шестнадцатеричном виде. Другая версия загрузчика или Minecraft не выбирается молча.

`client` принимает `required`, `optional`, `unsupported`. Автоматически устанавливаются только `required`; их зависимости тоже должны быть обязательными и присутствовать в списке. `dependencies` содержит `artifactId`, а `modIds` — идентификаторы внутри мода. Серверный publisher выдаёт `source.type: external`; протокол лаунчера также понимает `modrinth` с точными `projectId` и `versionId`.

Пределы: JSON до 1 МиБ, глубина 16, до 2048 файлов, до 512 МиБ на файл и до 4 ГиБ на план. Разрешены только имена JAR без каталогов. Абсолютные пути, `..`, ADS, имена устройств Windows, коллизии имён и ссылки на другие каталоги отклоняются. Публикуются только перечисленные файлы из `client-pack`; конфиги и произвольные пути не обслуживаются.

Внешний источник использует HTTPS без перенаправлений. Серверный HTTP-сервис размещается за HTTPS-прокси; `baseUrl` содержит его origin без вложенного пути. Лаунчер не отправляет cookies и авторизацию источнику. Для локального теста допустим HTTP URL с буквальным loopback: явно сохранённый с разрешением локальной синхронизации либо обнаруженный через status при подключении к буквальному loopback IP. Произвольные LAN-источники не разрешены.

## IPC: мод и лаунчер

Текущая реализация использует Windows named pipes. Лаунчер создаёт новую сессию для конкретной JVM и передаёт ей окружение:

| Переменная | Значение |
| --- | --- |
| `MECHANICA_BRIDGE_PIPE` | Имя локального канала |
| `MECHANICA_BRIDGE_SESSION` | UUID сессии |
| `MECHANICA_BRIDGE_TOKEN` | Одноразовый секрет сессии |
| `MECHANICA_BRIDGE_INSTANCE` | ID сборки |

Если всех переменных нет, мост не перехватывает обычное подключение. Неполное или неверное окружение не принимается как действующая сессия. Секрет используется только в локальном handshake: он не передаётся серверу и не записывается в журнал. Лаунчер проверяет пользователя Windows, PID и время запуска привязанного процесса.

Каждый кадр содержит длину JSON в байтах (`uint32`, little-endian) и UTF-8 JSON. Максимальный размер — 16 КиБ. Сначала `BridgeHello` передаёт `bootstrapVersion: 1`, `sessionId`, `instanceId`, `token` и `protocols: [{"major":1,"minor":0}]`. Ответ `BridgeReady` подтверждает выбранные `protocolMajor`, `protocolMinor`, `sessionId`, `instanceId`.

После handshake запрос содержит `type`, `protocolMajor`, `protocolMinor`, `sessionId`, `instanceId`, `requestId`, `expiresUtc` и `payload`. Ответ повторяет session/instance/request ID. Для каждого нового запроса клиент создаёт UUID `requestId`; текущая реализация выдаёт ему срок 14 минут, лимит лаунчера — 15 минут.

| Сообщение | Данные и действие |
| --- | --- |
| `PrepareConnection` → лаунчер | `host`, `port`, `knownRevision`. Лаунчер находит сохранённый сервер для этой сборки, получает список и согласие. |
| `Plan` → мод | `planId`, `revision`, `manifestSha512`, `downloadBytes`, `restartRequired`. Изменения ещё не применены. |
| `Apply` → лаунчер | `planId` ранее согласованного плана; начинает скачивание во временный каталог. |
| `Cancel` → лаунчер | `planId`, если он уже известен; пустой payload отменяет ожидание подготовки или согласия до получения плана. |
| `Result` → мод | `status: ready`, `cancelled`, `restart_required` либо `error`; при ошибке передаётся `code` и при необходимости сообщение. |

`ready` продолжает исходное подключение. `cancelled` прекращает текущую попытку. `restart_required` означает, что файлы подготовлены: клиент штатно завершает игру через игровой поток. Повторный запуск выполняет лаунчер, отдельного сообщения `Reconnect` текущему клиенту не требуется.

Отмена отправляется по отдельному авторизованному соединению, чтобы она работала во время ожидания `PrepareConnection` или загрузки. Повтор одного requestId с тем же содержимым не запускает работу заново; другое содержимое под тем же ID отклоняется. Применение одного planId повторно запрещено.

## Сохранность файлов и ошибки

Лаунчер ведёт отдельный реестр управляемых сервером файлов. Заменять и убирать можно только неизменённые записи этого реестра; совпадение имени или mod ID не разрешает удалить личный мод. Перед применением текущие хеши проверяются повторно. Исходные заменяемые файлы сохраняются, применение журналируется; после сбоя выполняется восстановление до следующего запуска игры.

Ошибка сети, несовместимый target, устаревший список, неверный хеш, отмена или конфликт не разрешают подключение с автоматически применённым непроверенным набором. Мост оставляет игрока на экране ошибки/отмены; обычное подключение без синхронизации остаётся отдельным выбором. `busy` сообщает о другой операции со сборкой. Автоматический перезапуск ограничен одной попыткой, личные миры, конфиги и ресурсы не очищаются.
