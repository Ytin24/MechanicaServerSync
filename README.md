# Mechanica Server Sync

Мод для синхронизации клиентских модов сервера через [Mechanica Launcher](https://github.com/Ytin24/MechanicaLauncher).

На клиенте передаёт попытку подключения лаунчеру. Лаунчер проверяет список модов, скачивает изменения, ждёт штатного выхода из игры и запускает её снова с тем же сервером. Без окружения Mechanica обычное подключение работает напрямую.

На выделенном сервере этот же JAR публикует только файлы, явно перечисленные администратором. Каталог `mods` автоматически не раздаётся. Fabric API для Fabric-вариантов не нужен.

## Клиент

В настройках нужной сборки Mechanica включить **Mechanica Server Sync**. Лаунчер установит подходящий мост. При подключении из Minecraft обновлённый лаунчер обнаружит адрес `descriptor.json` через обычный status ping сервера и предложит докачку. Добавлять сервер в избранное для этого не требуется.

Для автообнаружения серверный JAR тоже должен быть обновлён. Для старого сервера можно выбрать сборку в «Любимых серверах» и явно указать адрес `descriptor.json`, который дал администратор.

«Автодокачка модов» разрешает установку для сохранённого сервера. Без неё лаунчер покажет изменения и запросит подтверждение. Смена адреса, списка модов или сборки снимает это разрешение. Личные изменённые файлы дают конфликт и не перезаписываются.

Связь клиента с лаунчером сейчас использует Windows named pipes. Без включённой синхронизации лаунчер не создаёт эту сессию.

## Сервер

1. Выбрать JAR для версии сервера из `dist` и положить его в `mods`.
2. Рядом с `server.properties` создать `client-pack` и положить туда нужные клиентские JAR.
3. Создать `config/mechanica-sync.json` с одной строкой и запустить сервер обычным способом:

```json
{ "baseUrl": "https://mods.example.org" }
```

Остальное мод выясняет сам при каждом запуске:

| Что | Откуда берётся |
| --- | --- |
| Список файлов | Все `*.jar` из `client-pack`, каждый как `required` без зависимостей |
| `modIds` | Из `fabric.mod.json`, `quilt.mod.json`, `META-INF/mods.toml`, `META-INF/neoforge.mods.toml` или `mcmod.info`; если метаданных нет, из имени файла |
| `minecraft`, `loader`, `loaderVersion`, `targetId` | Из запущенного сервера |
| `serverId` | Создаётся один раз и хранится в `config/mechanica-sync.state.json` |
| `revision` | Растёт сама, только когда меняется набор или байты файлов; обычный перезапуск её не меняет |
| `expiresUtc` | 90 дней вперёд, продлевается при запуске, когда осталось меньше 30 дней |
| `port`, `bindAddress` | `25566` и `127.0.0.1` |

Чтобы обновить моды у игроков, достаточно заменить JAR в `client-pack` и перезапустить сервер. Файлы с пробелами, кириллицей и другими символами кроме латиницы, цифр и `._+-` пропускаются с предупреждением `MECHANICA_SYNC_SKIPPED_FILE` в журнале. Итог пишется строкой `MECHANICA_SYNC_CONFIG files=… revision=…`. Сервер, который работает без перезапуска дольше месяца, стоит перезапускать хотя бы раз в 30 дней, иначе список истечёт.

### Полная настройка

Любое поле, указанное в конфиге явно, имеет приоритет над автоматическим значением. Например, чтобы пометить мод как `optional` или задать зависимости, перечислите `files` вручную. Пример для локального сервера Fabric 1.20.1. `example-client-mod.jar` и его `modIds` заменить на реальные значения; явно указанные `minecraft`, `loader` и `loaderVersion` должны совпадать с запущенным сервером, иначе публикация не запустится.

```json
{
  "serverId": "b3a38c5e-593c-4bdd-9046-e019b3453eb0",
  "revision": 1,
  "expiresUtc": "2027-01-01T00:00:00Z",
  "targetId": "fabric-1.20.1",
  "minecraft": "1.20.1",
  "loader": "fabric",
  "loaderVersion": "0.19.5",
  "baseUrl": "http://127.0.0.1:25566",
  "bindAddress": "127.0.0.1",
  "port": 25566,
  "files": [
    {
      "artifactId": "example-client-mod",
      "modIds": ["example_client_mod"],
      "client": "required",
      "filename": "example-client-mod.jar",
      "dependencies": []
    }
  ]
}
```

Явный `serverId` должен быть UUID, срок действия задаётся в UTC с окончанием `Z`. `dependencies` содержит `artifactId` из того же списка; зависимости обязательного файла тоже должны быть обязательными. `optional` и `unsupported` автоматически не устанавливаются. `"files": "auto"` равносильно отсутствию поля.

Размеры и SHA-512 вычисляются при запуске по `client-pack`. Если `revision` указана явно, при изменении списка, файлов или срока действия её нужно увеличить вручную. Изменённый после публикации файл не отдаётся по старому хешу.

Мод объявляет адрес `http://127.0.0.1:25566/mechanica/descriptor.json` в ответе на status ping, когда HTTP-сервис успешно запущен. Игровой порт и HTTP-порт — разные настройки. Для локального теста подключаться к игровому серверу по `127.0.0.1`.

Для внешнего сервера нужен HTTPS-прокси перед HTTP-сервисом; его origin указать в `baseUrl`, например `https://mods.example.org`. Пути `/mechanica/` проксируются без изменения. При автообнаружении HTTP допускается только когда и игровой адрес, и адрес описания — буквальные loopback IP. Без конфига HTTP-сервис не запускается и объявление в status не добавляется.

## Сборка

Скрипт рассчитан на Windows и PowerShell. Для полного набора установить JDK 8, 17, 21 и 25; `JAVA_HOME` должен указывать на JDK 21. JDK 25 можно передать через `-Java25Home` или `JAVA_HOME_25_X64`. Gradle использует wrapper соответствующего проекта.

```powershell
./scripts/Build.ps1
./scripts/Build.ps1 -Targets fabric-1.20.1
```

`-JavaHome` задаёт JDK для обычных проектов, `-Java25Home` — для 26.x. `-SkipBuild` упаковывает готовые файлы без компиляции и Java-тестов. Упаковка проверяет наличие артефактов и обязательный `pack.mcmeta` Forge.

Результаты:

- `dist/*.jar` — моды для клиента и сервера;
- `dist/manifest.json` — каталог вариантов и SHA-512 для лаунчера;
- `dist/fixtures/*.jar` — отдельные моды для интеграционных тестов.

[CI](.github/workflows/build.yml) выполняет `check build` через этот же скрипт при push в `master`, в pull request и вручную. Артефакт `mechanica-server-sync` содержит рабочие JAR и манифест; тестовые fixture в него не входят. CI-сборка не запускает Minecraft.

## Протокол и тестовый мод

[HTTP и IPC 1.0](docs/protocol.md) описывают формат сообщений, публикацию файлов и применение изменений. Общий код находится в [common](common/src/main/java/ru/mechanica/sync); игровые точки входа и Mixins зависят от версии Minecraft.

Fixture нужен только для проверки настоящего входа на сервер. Маркеры журнала: `MECHANICA_SYNC_FIXTURE_INIT`, `MECHANICA_SYNC_FIXTURE_SERVER_JOIN`, `MECHANICA_SYNC_FIXTURE_CLIENT_JOIN`. Сервер пишет `MECHANICA_SYNC_FILE_REQUEST` при отдаче файла. Только fixture поддерживает `-Dmechanica.smoke=true` и штатно закрывает тестовый клиент через две секунды после входа.
